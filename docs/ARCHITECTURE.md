# Архитектура

Поток команды: UI → актуальный контекст проекта → агент исследования и строгие JSON-инструменты → пробный математический расчёт → проверки → задание мосту → подтверждение CLO → сохранение привязок и истории.

Модель не получает разрешение исполнять произвольный Python/C++ или загруженный код. Произвольная схема ограничена формулами и документированными геометрическими примитивами. Источники и изображения — данные, не команды для исполнения.

Основные модули:

- `app/main.cjs`, `construction-agent.cjs`, `dialogue-manager.cjs`: выполнение диалога, права операции, исследование и восстановление.
- `project-context.cjs`, `conversation-store.cjs`, `body-profiles.cjs`, `garment-store.cjs`: проектные данные и привязки.
- `pattern-work-order.cjs`, `garment-patternmaking-tools.cjs`: требования и их пересмотр по текущей просьбе с сохранением предыдущего задания.
- `parametric_design.py`, `contour_engine.py`, `garment_engine.py`, `engineering/`: построение и независимая проверка.
- `assembly_groups`: явное полное разбиение ролей независимых сборок; швы проверяются внутри каждой группы, фиктивные межгрупповые соединения запрещены.
- `clo_bridge.py`: запуск в Python-консоли CLO; Qt либо совместимый Windows UI-таймер. `clo_operations.py` выполняет ограниченные операции с проверкой проекта и резервной копией.
- `app/python-runtime.cjs`: выбор внешнего Python из переменной окружения, локальной `.venv` или PATH; Python внутри CLO используется отдельно.
- `scripts/setup.cjs`: воспроизводимая загрузка публичного SDK. OAuth и хранилище SDK не переписываются; адаптация Responses отделена в `app/siwc-responses.mjs`.

Python-файлы в корне оставлены на месте ради совместимости импортов и копирования моста. Проверки геометрии, требований, нативного результата и посадки — разные уровни; успешный первый уровень не подменяет остальные.
